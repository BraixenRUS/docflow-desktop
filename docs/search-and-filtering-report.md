# Реализация поиска, фильтрации документов и синхронизации статусов с Backend API

**Проект:** DocFlow Desktop  
**Тип работы:** развитие frontend-прототипа и интеграция с серверной очередью задач

## 1. Цель

Реализовать в прототипе `prototype/document-graph` механизмы поиска и многокритериальной фильтрации документов, панель списка документов с отображением актуальных статусов фоновой обработки, а также подключить автоматическое получение данных от Backend API без перезагрузки страницы.

## 2. Подключение к Backend API и синхронизация статусов

Взаимодействие между клиентской частью (React + Vite) и серверной частью (ASP.NET Core Web API, `.NET 9`) организовано по HTTP через локальное проксирование запросов `/api` на `http://localhost:5000` в `vite.config.js`.

В модуле `prototype/document-graph/src/api.js` реализована функция `fetchTasks()`, которая запрашивает список задач методом `GET /api/tasks` и преобразует серверную модель `DocumentTask` в формат документа клиентского приложения.

### Таблица соответствия статусов

| Статус Backend (`DocumentTask.Status`) | Внутренний статус Frontend | Отображение в интерфейсе |
|---|---|---|
| `Queued` | `queued` | В очереди |
| `Running` | `processing` | В обработке |
| `Done` | `completed` | Обработка завершена |
| `Error` | `error` | Ошибка обработки |

*(Примечание: для локального демонстрационного набора документов также сохранены детальные тестовые статусы `recognizing` и `analyzing`).*

### Автоматическое обновление (Polling)

В компоненте `src/App.jsx` через `useEffect` настроен периодический опрос сервера с интервалом 3 секунды (`setInterval`). При получении ответа задачи с сервера (`source: 'api'`) объединяются с демонстрационным набором документов без потери текущего состояния выбранных фильтров и выделенного документа. При недоступности сервера выводится предупреждение, а интерфейс продолжает работать с локальными данными.

## 3. Реализованная функциональность поиска и фильтрации

В рабочую область приложения (`.workspace`) добавлена левая боковая панель (`.sidebar`), выстроенная в соответствии с трёхколоночной структурой дизайн-макета:

1. **Поиск документов (`searchQuery`):**
   - Выполняется без учёта регистра по названию документа (`label`) и его описанию (`description`).
2. **Фильтрация по типу документа (`selectedType`):**
   - Список доступных типов формируется динамически на основе загруженных документов (включая категорию `Другой` для файлов, поступающих с Backend API).
3. **Фильтрация по статусу обработки (`selectedStatus`):**
   - Позволяет отобрать документы на конкретном этапе обработки (`queued`, `processing`, `recognizing`, `analyzing`, `completed`, `error`).
4. **Фильтрация по дате загрузки (`selectedDate`):**
   - Фильтрует документы по дате создания/загрузки в формате `ДД.ММ.ГГГГ`.
5. **Интерактивный список документов и связь с графом:**
   - В левой панели отображается отфильтрованный список карточек документов с цветовой индикацией типа и текущего статуса обработки.
   - Выбор документа в списке синхронизирован с графом `@xyflow/react`: клик по элементу списка выделяет соответствующий узел на графе и открывает детальную карточку в правой панели.
   - На графе динамически отображаются только узлы, прошедшие фильтрацию (`filteredDocuments`), и связи между видимыми узлами (`visibleEdges`).
   - В нижней части левой панели выводится актуальная сводка по количеству документов и связей в текущем графе.

## 4. Ограничения текущей реализации

- Серверная модель `DocumentTask` на текущем этапе не хранит тип документа и связи между файлами, поэтому задачам, полученным через `GET /api/tasks`, на стороне клиента присваивается тип `Другой`, а на графе они размещаются как отдельные узлы с автоматическим расчётом координат.
- Серверная обработка пока представляет собой временную имитацию (задержка выполнения в фоновом воркере) без реального OCR-распознавания и ИИ-анализа содержимого.
- Задачи на сервере хранятся в оперативной памяти (`TaskQueue`) и сбрасываются при перезапуске Backend API.

## 6. Вывод

В прототипе `prototype/document-graph` реализованы поиск и фильтрация документов по типу, дате загрузки и статусу обработки, добавлена панель списка документов с индикацией состояний и настроена периодическая синхронизация с Backend API. Все изменения согласованы с архитектурой React Flow и общей трёхколоночной компоновкой интерфейса.
