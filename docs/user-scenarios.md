# Пользовательские сценарии

Описание основных процессов работы пользователя с приложением.

## Сценарий 1. Загрузка и распознавание документа

**Предусловие:** приложение запущено, локальная БД доступна.

1. Пользователь выбирает один или несколько файлов через проводник либо перетаскивает их в окно программы.
2. Система проверяет формат файла (PDF, DOCX, PNG, JPG), целостность и наличие дубликата в базе (по контрольной сумме).
3. Файл копируется в локальную папку проекта, в БД создается запись.
4. Запускается обработка документа:
   - если в файле есть текстовый слой — текст извлекается напрямую;
   - если это скан или фото — запускается локальный OCR.
5. Система определяет тип документа (договор, акт, счет, накладная) и вытаскивает реквизиты: номер, дату, контрагентов, сумму.
6. По найденным реквизитам система ищет связанные документы в базе (например, договор для загруженного акта).
7. Если найдено однозначное совпадение, связь проставляется автоматически.
8. Документ получает статус «Обработан». Пользователь видит готовую карточку с заполненными полями и привязанными файлами.

---

## Сценарий 2. Просмотр и редактирование связей вручную

1. Пользователь открывает карточку документа и переходит на вкладку «Связи» (список или граф).
2. Система показывает текущий файл и привязанные к нему документы с типами связей («Основной договор», «Акт», «Счет», «Приложение»).
3. **Добавление связи:**
   - пользователь нажимает «Добавить связь»;
   - находит нужный документ через поиск;
   - выбирает тип связи (родительский, дочерний, сопутствующий) и нажимает «Сохранить»;
   - система проверяет, нет ли зацикливания, сохраняет запись в БД и обновляет граф.
4. **Удаление связи:**
   - пользователь выбирает связь в списке или на графе и нажимает «Удалить»;
   - после подтверждения запись о связи удаляется из БД (сами файлы остаются в системе).

---

## Сценарий 3. Поиск и фильтрация

1. Пользователь вводит запрос в поисковую строку (по названию, номеру или тексту внутри документа) и/или выбирает фильтры: тип документа, контрагент, период дат, статус.
2. Система ищет совпадения в таблице реквизитов и по полнотекстовому индексу.
3. На экран выводится список подходящих документов.
4. По клику на документ открывается его карточка и окно предпросмотра файла.

---

## Сценарий 4. Удаление документа

1. Пользователь нажимает кнопку «Удалить» в списке или внутри карточки документа.
2. Система проверяет, есть ли у файла привязанные дочерние документы:
   - если связей нет — выводится обычное окно подтверждения, после чего запись стирается из БД, а файл удаляется с диска;
   - если к документу привязаны другие файлы — система предлагает выбрать: удалить только сам файл (отвязав остальные) или удалить всю цепочку целиком.
3. После подтверждения база и список документов на экране обновляются.
