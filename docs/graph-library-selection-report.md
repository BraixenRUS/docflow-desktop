# Выбор библиотеки для визуализации графа документов

**Проект:** DocFlow Desktop\
**Тип работы:** исследование и создание MVP

## 1. Цель

Выбрать библиотеку для отображения связей между документами и проверить
её основные возможности на простом прототипе.

## 2. Рассмотренные библиотеки

-   **React Flow** --- библиотека для интерактивных графов и диаграмм в
    React. Позволяет создавать собственные узлы, отображать связи,
    перемещать элементы и масштабировать рабочую область.
-   **Cytoscape.js** --- библиотека для визуализации и анализа графов.
    Подходит, если потребуется исследовать структуру связей и
    использовать алгоритмы анализа.
-   **vis-network** --- библиотека для интерактивного отображения сетей
    с настройкой узлов и связей.

## 4. Почему выбран React Flow

Для прототипа выбран **React Flow**, потому что приложение
разрабатывается на React, а библиотека позволяет создавать узлы как
компоненты интерфейса.

Для текущей задачи нужны базовые возможности: показать документы и связи
между ними, перемещать узлы, масштабировать граф и открывать информацию
о выбранном документе. React Flow позволяет реализовать эти функции без
лишней сложности.

Cytoscape.js стоит рассмотреть повторно, если в дальнейшем понадобится
более глубокий анализ графа. Производительность разных библиотек в
одинаковых условиях не сравнивалась, поэтому утверждать, что одна из них
быстрее остальных, нельзя.

## 5. Реализованный MVP

В прототипе используется React, Vite и пакет `@xyflow/react`.

Граф содержит 10 тестовых документов, связанных с условным процессом
поставки оборудования: договор, спецификация, счёт, платёжное поручение,
накладная, акт приёмки, счёт-фактура, письмо, дополнительное соглашение
и акт сверки.

Реализованы следующие функции:

-   отображение документов и связей;
-   перемещение узлов;
-   масштабирование и навигация по графу;
-   выбор документа нажатием;
-   отображение типа, даты, ID и описания документа в боковой панели;
-   тёмное оформление интерфейса.

Данные заданы вручную. Прототип пока не распознаёт реальные документы и
не определяет связи с помощью ИИ.

## 6. Предварительная проверка производительности

Во время разработки отдельные взаимодействия проверялись в Chrome
DevTools при разном количестве узлов.

  -----------------------------------------------------------------------
                          Количество узлов Наблюдение
  ---------------------------------------- ------------------------------
                                        10 Одно выбранное событие Pointer
                                           заняло около 1,11 мс

                                       100 Большинство наблюдений были
                                           около 2 мс, одно событие ---
                                           около 64,73 мс

                                       500 Одно событие заняло около
                                           264,01 мс
  -----------------------------------------------------------------------

Эти результаты предварительные: тесты проводились в небольшом
количестве, условия не были полностью стандартизированы, а расширения
браузера могли влиять на результаты. Они не являются полноценным
сравнением библиотек. При увеличении графа требуется дополнительное
тестирование.

## 7. Вывод

React Flow выбран как подходящая библиотека для текущего MVP благодаря
интеграции с React, настройке внешнего вида узлов и наличию нужных
интерактивных функций. Созданный прототип демонстрирует граф из 10
документов и позволяет просматривать сведения о каждом из них.

Перед использованием на больших наборах данных необходимо провести более
строгие тесты производительности. Также отдельно предстоит проверить
автономную работу всего приложения.
