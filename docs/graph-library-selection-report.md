# Выбор библиотеки для визуализации графа документов

**Проект:** DocFlow Desktop  
**Тип работы:** исследование и создание MVP

## 1. Цель

Выбрать библиотеку для отображения связей между документами и проверить её основные возможности на работающем прототипе.

В рамках работы необходимо оценить удобство интеграции с React, возможности настройки внешнего вида графа, интерактивность и пригодность библиотеки для дальнейшего развития проекта.

## 2. Рассмотренные библиотеки

- **React Flow** — библиотека для создания интерактивных графов и диаграмм в React. Позволяет создавать собственные типы узлов, отображать связи, перемещать элементы и масштабировать рабочую область.
- **Cytoscape.js** — библиотека для визуализации и анализа графов. Подходит для работы со сложными структурами связей и применения алгоритмов анализа.
- **vis-network** — библиотека для интерактивного отображения сетей с возможностью настройки узлов, связей и поведения графа.

## 3. Сравнение

| Критерий | React Flow | Cytoscape.js | vis-network |
|---|---|---|---|
| Интеграция с React | Удобная, предусмотрена библиотекой | Требует интеграции | Требует интеграции |
| Отображение узлов и связей | Да | Да | Да |
| Настройка внешнего вида | Через React-компоненты | Через API и стили | Через настройки библиотеки |
| Интерактивность | Перемещение, масштабирование, выбор узлов | Перемещение, масштабирование, взаимодействие с графом | Перемещение, масштабирование, взаимодействие с графом |
| Анализ структуры графа | Не основное назначение | Одна из основных возможностей | Ограниченный набор встроенных возможностей |
| Подходит для MVP | Да | Да, но часть возможностей избыточна для текущей задачи | Да |

## 4. Почему выбран React Flow

Для прототипа выбран **React Flow** (пакет `@xyflow/react`), поскольку интерфейс DocFlow Desktop разрабатывается с использованием React.

Основное преимущество библиотеки — возможность создавать узлы графа в виде обычных React-компонентов. Это позволяет оформлять карточки документов с собственными элементами интерфейса, статусами обработки и дополнительной информацией.

Для текущей задачи требуются следующие возможности:

- отображение документов и связей между ними;
- перемещение узлов мышью;
- масштабирование и навигация по рабочей области;
- выбор документа нажатием;
- отображение дополнительной информации о выбранном документе;
- настройка внешнего вида узлов и связей.

React Flow предоставляет необходимые инструменты через готовый API и позволяет реализовать перечисленные функции без разработки механики графа с нуля.

**Размер и производительность.** Отдельное количественное сравнение размеров установленных библиотек не проводилось. При проверке production-сборки прототипа общий размер JavaScript-бандла составил 407,60 КБ (128,99 КБ в gzip). Это размер всего бандла приложения, а не самой библиотеки React Flow.

Производительность разных библиотек в одинаковых условиях не сравнивалась, поэтому утверждать, что React Flow быстрее Cytoscape.js или vis-network, нельзя.

Cytoscape.js стоит рассмотреть повторно, если в дальнейшем понадобится более глубокий анализ структуры графа и применение алгоритмов обработки связей.

## 5. Реализованный MVP

В прототипе используются React, Vite и пакет `@xyflow/react`.

Тестовые данные вынесены в отдельный JSON-файл:

`prototype/document-graph/src/data/mockGraph.json`

Граф содержит **10 тестовых документов и 14 связей**. Документы относятся к условному процессу поставки оборудования:

- договор;
- спецификация;
- счёт;
- платёжное поручение;
- накладная;
- акт приёмки;
- счёт-фактура;
- письмо;
- дополнительное соглашение;
- акт сверки.

Для проверки интерфейса документам назначены различные статусы обработки:

- `queued` — ожидает обработки;
- `recognizing` — распознавание;
- `analyzing` — анализ;
- `completed` — обработка завершена;
- `error` — ошибка обработки.

### Реализованные функции

- отображение документов в виде отдельных узлов графа;
- отображение связей между документами с подписями;
- перемещение узлов мышью;
- сохранение положения узлов при обновлении их данных и статусов;
- масштабирование и навигация по рабочей области;
- выбор документа нажатием;
- отображение ID, типа, даты и описания документа в боковой панели;
- отображение статуса и прогресса обработки;
- имитация изменения статусов обработки;
- возможность сброса выбора документа и тестирования отдельных состояний;
- тёмное оформление интерфейса.

Данные заданы вручную и используются для демонстрации возможностей интерфейса. Прототип пока не распознаёт реальные документы и не определяет связи между ними с помощью ИИ. Связи в тестовом наборе являются демонстрационными.

## 7. Предварительная проверка производительности

Во время разработки отдельные взаимодействия проверялись в Chrome DevTools при разном количестве узлов.

| Количество узлов | Наблюдение |
|---:|---|
| 10 | Одно выбранное событие Pointer заняло около 1,11 мс |
| 100 | Большинство наблюдений — около 2 мс, одно событие — около 64,73 мс |
| 500 | Одно событие заняло около 264,01 мс |

**Ограничения проверки:** это предварительные наблюдения, а не полноценный нагрузочный тест. Измерения проводились в разных условиях, количество замеров небольшое. Поэтому результаты нельзя считать точным сравнением производительности библиотек или гарантией стабильной работы на больших графах.

Для более точной оценки потребуется провести повторные измерения в одинаковых условиях, использовать одинаковые тестовые данные и анализировать не только отдельные события Pointer, но и общую отзывчивость интерфейса.

## 8. Вывод

Для текущего MVP выбрана библиотека React Flow благодаря удобной интеграции с React, возможности создавать собственные компоненты узлов и наличию необходимых инструментов для интерактивной работы с графом.

Создан работающий прототип, который отображает 10 тестовых документов и 14 связей между ними. Реализованы перемещение узлов, масштабирование, выбор документов, просмотр информации о них и демонстрация различных статусов обработки.

Основные функциональные требования прототипа проверены, production-сборка выполняется успешно.

Перед использованием на больших наборах данных необходимо провести более строгие тесты производительности. Также отдельно предстоит проверить интеграцию с реальными данными и автономную работу всего приложения.
